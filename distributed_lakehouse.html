Architectural Guardrail

Governing Principles: Data Gravity

Highlighted nodes and amber flows show where data remains anchored and how compute, metadata, and queries move around it:

1. Move Compute to Data — Never Raw Data Across the WAN
Transformations, XML/JSON parsing, and Iceberg compaction execute locally next to storage (AWS Glue/EMR on S3; Spark on K8s/Trino on MinIO S3).
2. Move Metadata & Curated Data When Needed — Never Huge Source Data
Lightweight metadata, lineage, and policies sync freely via DataHub, and small, curated, governed Gold datasets or aggregates may move when needed—massive raw source datasets remain anchored at home.
3. Federated Predicate Pushdown First; No Bulk Raw Replication
Starburst Galaxy / Trino pushes filters and aggregations down to local compute via Iceberg REST, transferring only minimal governed results or curated outputs across the WAN.
4. Local Enforcement at the Storage Boundary
Fine-Grained Access Control (AWS Lake Formation & Apache Ranger) is enforced locally at query time rather than duplicating masked extracts.
5. Ephemeral Sovereign Landing, Zero Direct Egress
On-prem MinIO Landing enforces 7–30d TTL with no direct BI access or WAN egress; Iceberg Bronze retains the durable audit record locally.
ROI-Justified Compute Strategy & Maturity Journey

Local Compute Plane: Initial Setup & Low-Disruption Evolution

★ RECOMMENDED FOUNDATION

Amazon EMR Serverless — Optimal ROI From Day One

Scale-to-Zero + Pre-Warmed Pools
Better Cost & Performance at Low Volume

Per-second billing on exact vCPU & RAM consumed (with Graviton options and no rigid 2-DPU floor) plus scale-to-zero when idle avoids wasted startup spend.

Superior Scale & Speed as Tenants Grow

Pre-initialized warm worker pools eliminate 1–2 min cold starts for frequent steady, SLA-bound batch runs while bypassing Glue's 30–50 concurrency ceiling with per-tenant Spark isolation.

Low-Disruption Maturity Journey (Zero Spark Rewrites)

Upstream (S3 → SNS → Lambda → EventBridge) & Iceberg stay identical — only the submit target swaps

Compute Options Overview (Greenfield Evaluation)

Option Status / Tag Role & Fit Key Trade-Offs
EMR Serverless RECOMMENDED FOUNDATION Best default foundation across low-volume starts & scaling multi-tenant SLA-bound batch runs. Beats Glue on cost & speed from day one—fine-grained vCPU/RAM billing, scale-to-zero, plus pre-warmed worker pools.
AWS Glue Entry / Low-Frequency Best suited for infrequent batch jobs (≥2 hr intervals) & modest tenant counts. 1–2 min cold starts, fixed 2-DPU floor, and 30–50 account concurrency ceiling bottleneck cost & scale.
EMR on EC2 Mature SLA Tier Target state for steady, flat, high-volume AWS-native data sources. Lowest unit compute cost for continuous load (Savings Plans / RIs), but carries cluster ops overhead.
EMR on EKS Mature Hybrid / SLA Tier Target state if unifying Spark on Kubernetes across AWS & on-prem (NetApp StorageGRID / MinIO). Strongest hybrid portability & pod bin-packing, but highest platform engineering overhead.

4–5 Dense RHEL Servers • Batch-Only First

Centralized Enterprise Control Plane

Business Catalog, Master Data (MDM) & Identity (IDM)

Enterprise Business Catalog & Governance Control Plane

Acts as the single pane of glass for enterprise data discovery, business context, and governance standards across AWS, On-Premises, and MDM—without moving raw data.

1. Discoverability & Lineage

Automatically harvests schemas, tables, and assets from AWS Glue, Apache Polaris, and MDM, giving business and technical users unified search and end-to-end lineage.

2. Business Cataloging & Glossary

Maps technical tables and columns to plain-English business terms, domain owners, SLAs, data quality scores, and certified data product contracts.

3. Standards, Taxonomy & Policy

Defines enterprise classification taxonomies (PII, Confidential, Sovereign) and access policies once, pushing them down to Lake Formation and Apache Ranger for local enforcement.

Available Products (Open Source & Commercial)

★ Open Source (Shown in Architecture)

DataHub (Open Source), OpenMetadata, and Apache Atlas — strong API-first metadata graphs, OpenLineage support, and zero vendor lock-in.

Commercial / SaaS Enterprise

Collibra, Alation, Atlan, and Microsoft Purview — turnkey stewardship workflows, compliance reporting, and managed SaaS operations.

Centralized Master Data Management (MDM)

Separate from Lakehouses • Published to DataHub

Maintains authoritative, enterprise-wide "golden records" independently of any single lakehouse. Publishes its certified assets to DataHub for discovery and exposes standardized master entities to AWS Lakehouse, On-Prem Lakehouse, and operational apps.

Core Master Domains

Standardized Clients / Customers, Products & SKUs, Suppliers, Chart of Accounts, and Locations—ensuring every system uses identical IDs and descriptions.

Standardization & Survivorship

Deduplication, entity resolution, match-and-merge rules, stewardship approval workflows, and cross-reference (XREF) mapping across cloud and on-prem sources.

Exposed Serving Endpoints

Publishes golden records via REST / GraphQL APIs, real-time Event Streams, and open Apache Iceberg golden tables referenced by both lakehouses.

Implementation & Product Options

★ Open Source & Self-Implemented on Iceberg

Self-Implemented Iceberg MDM (PySpark entity resolution + dbt + Apache Iceberg golden tables + REST APIs) or open-source tools like Pimcore—zero proprietary format lock-in.

Commercial MDM Platforms

Reltio, Informatica MDM, Profisee, and Stibo Systems — pre-built survivorship UIs, stewardship workflows, and industry data models.

Centralized Identity Management (IDM / IdP)

Referenced Across All 5 Tiers

Provides the single enterprise source of truth for human and machine identities, authentication, and group memberships—referenced consistently by DataHub, AWS Lakehouse, On-Prem Lakehouse, Federation, and Consumption Gateways.

SSO & Federation

Centralized authentication via OIDC / OAuth 2.0 and SAML 2.0 with MFA, eliminating siloed local credentials across cloud and on-premises tools.

Identity Propagation for FGAC

Passes verified user & group claims end-to-end through BI, APIs, and MCP servers down to AWS Lake Formation and Apache Ranger for consistent row/column security.

Lifecycle & Audit (SCIM)

Automated joiner/mover/leaver provisioning via SCIM and centralized access audit trails for regulatory compliance.

Common Enterprise IDM / IdP Platforms

Microsoft Entra ID (Azure AD), Okta, Ping Identity, AWS IAM Identity Center, and open-source Keycloak (ideal for sovereign or hybrid on-prem OIDC brokering).

Unified Query Federation — Optional Layer

Add Only When Cross-Lakehouse Joins Are Needed

Because both lakehouses store data in open Apache Iceberg, downstream consumers (BI, ML, Apps, AI) can read directly from AWS or On-Premises individually—query federation is not mandatory on Day 1.

Direct Local Consumption (Default / No Federation Needed)

Consumers query each lakehouse directly using native engines—Amazon Athena / EMR in AWS or Local Trino / Spark on-prem—with zero extra hop, lower latency, and full local Lake Formation / Ranger governance.

When to Introduce Query Federation

Add a federation engine only when business use cases genuinely require live cross-environment SQL joins (joining AWS + On-Prem tables in a single query) with predicate pushdown so raw data stays anchored.

Query Federation Options (If Required)

★ Trino (Open Source)

Industry-standard open-source distributed SQL engine with native Iceberg REST connectors (AWS Glue & Apache Polaris) and $0 software licensing.

Starburst Galaxy / Enterprise

Managed/commercial Trino adding enterprise RBAC/Ranger integration, query caching, cross-cloud pushdown acceleration, and 24/7 SLAs.

Dremio / Athena Federation

Dremio for Iceberg-native SQL + Reflections caching, or Athena Federated Query for lightweight AWS-centric cross-source lookups.
